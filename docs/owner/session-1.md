# 所有者の作業（1 回目）: 実エクスポートの確認・拡張の通し操作・DEV03

D-0004 により、所有者の手作業は依頼中の公式エクスポートが届いた時点で 1 回にまとめる。本書はその回の手順と、報告してよいもの・いけないものをまとめる。実会話・実エクスポート・認証情報は、Issue・PR・AI エージェントへ渡さない（CLAUDE.md）。

所要の目安: 1〜2 時間（DEV03 を行う場合はその分を加える）。

## 0. 準備（5 分）

1. リポジトリを最新の `main` にし、`pnpm install --frozen-lockfile` と `pnpm build` を実行する。
2. Chrome の `chrome://extensions` でデベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」で `dist/` を読み込む。以前の版を読み込んでいれば削除してから読み込む（保存データの形式は変わっていない）。

## 1. 実エクスポートの確認（DEV05、20 分）

手順は `docs/p1/DEV05-owner-check.md` のとおり。任意のタブで拡張のアイコンを押して管理画面を開き、ZIP を取り込む。

報告してよいもの:
- 状態（完了 / 一部のみ / 失敗）と取り込み件数。
- 問題項目のコードごとの件数（例: `unknown-entry` 3 件）。
- 構造レポートの内容（タイトル・本文・ID・ファイル名を含まないことを目で確かめてから）。特に `messageCoverage`（本文の取得範囲の内訳）と `unknownExtensions`。

報告しないもの: ZIP、タイトル、本文、問題項目の括弧内のファイル名。

## 2. 拡張の通し操作（20 分）

取り込んだ状態のまま、次を順に行い、期待どおりでなかった点だけを記録する。

| # | 操作 | 期待 |

| 2-2 | 検索語を入れる（日本語・英語・全角/半角を混ぜる） | 「一致 / 不一致 / 判定不能」の件数が出る。判定不能は本文の一部が未取得の会話 |

## 3. 判断（10 分）

次を決めて伝える。

1. 実行中に KEEP の保存先が使えなくなった場合（ロック・別タブの変更など）、計画を「失敗」にして一覧の取り直しを求める（現在の仕様）か、「一時停止」にして再確認後に続けられるようにするか。
2. 結果を確かめていない書き込みがある間の復旧を、手動の確認（現在の仕様。記録に ID を残さない）のままにするか、ID を KEEP と同じ鍵で暗号化して残し、次回に自動で照合できるようにするか（KEEP の保存形式に関わるため、選ぶ場合は別の Proposal にする）。
3. DEV03（下の 4）を今回行うか、後にするか。

## 4. DEV03: 実画面での確認（所有者の Adapter のため、任意・1〜2 時間）

ChatGPT の画面から一覧を取り、削除を実行する部分は所有者が用意する（D-0004）。P-0009 の枠組みにその部分を差し込むには、次の事実を使い捨ての会話で確かめ、記録しておく必要がある。確かめられなかった項目があれば、対応する能力（自動削除など）は無効のままになる（P-0009 第 1 節）。

準備: 確認専用の使い捨て会話を 5 件以上作る（実際の会話を使わない）。個人ワークスペースであることを確かめる（D-0002）。

| # | 確かめること | 記録すること（値そのものではなく「何で分かるか」） |
|---|---|---|
| 4-1 | 公式 UI の削除が送る要求と、所有者の Adapter が送る要求が同じであること | 方式・パスの形（ID は伏せる） |
| 4-2 | 削除・非表示・アーカイブ・アクセス不可の 4 つの会話で、対象 ID を直接読んだ応答の違い | 「削除済み」を示す値があるか（`item-deleted-marker`）。404 や空の応答しかないなら、自動削除は使えない |
| 4-3 | 削除後の状態が公式 UI での削除後と同じであること（一覧、アーカイブ一覧、検索、直接 URL） | 各画面で見えるかどうか |
| 4-4 | 一覧の取得: ページの続きの指定、総数、取得中に会話を追加・削除したときの振る舞い | 走査が安定か（`complete` にできるか） |
| 4-5 | 主体（アカウント・ワークスペース）の確認方法と、各応答から主体を得る方法 | どの応答のどの項目で分かるか |
| 4-6 | 更新の検出に使える項目（更新日時など）の意味と単位、更新で必ず変わるか | `updateDetector` に使えるか |
| 4-7 | 要求の間隔の目安（429 が返る条件） | 間隔の値 |
| 4-8 | KEEP を付けた会話が、削除の対象にならないこと（枠組みと Adapter をつないだ後） | 結果 |

報告してよいもの: 上の表の「記録すること」。ID・タイトル・本文・トークン・Cookie・応答の全文は報告しない。
