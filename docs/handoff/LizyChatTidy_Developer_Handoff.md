## 01 / 目的と対象範囲

### 合意済みの方向性

名称はLizyChatTidy。利用者自身のWeb上のチャット履歴から、残す会話を選び、不要な会話を管理・削除する。Chrome拡張として公開し、コード、権限、データ処理、配布物を検証可能にする。開発者向け収集サーバーは持たない。

| 対象 | 扱い |
| --- | --- |
| ChatGPTのWeb会話 | 対象。対象プラン・個人/組織ワークスペースは検証結果で限定する。 |
| Claude Code on the web | 対象。claude.ai/codeから利用するクラウドセッション。 |
| 通常のClaude Webチャット | 初期対象外。Claude Codeのセッションと混同しない。 |
| ローカルJSONL・CLI履歴 | 対象外。Agent SDKやNative Messagingの連携を必須にしない。 |
| アカウント削除・全削除 | 対象外。会話単位の対象IDに限定する。 |
| メモリ・ファイル・Git成果物 | 削除対象外。会話削除だけで全情報が消えると説明しない。 |

### 提供価値

タイトル・取得済み本文の検索、取得範囲を明示した一覧、KEEP、タグ、範囲選択、削除候補の確認、結果照合を一つの画面で扱う。本文が未取得の項目は、全文検索済みと表示しない。

### 未確定事項

両サービスの全履歴取得方法、DOMからの安定ID・主体識別、取得上限、更新検知、公開APIの適用可能性、操作の許可範囲はP0で確定する。対応OSやUI言語も実測なしに広く宣言しない。

## 02 / 公式文書と検証の境界

| 区分 | 確認事項・設計への影響 |
| --- | --- |
| 公式に確認 | ChatGPTには会話単位の削除と確認操作がある。アーカイブは削除ではない。[S01] |
| 公式に確認 | Claude Codeのクラウドセッションには削除導線と確認があり、取り消せない。[S02] |
| 公式に確認 | ChatGPTには対象アカウント向けの公式ZIPエクスポートがある。[S03] |
| 公式に確認 | Chrome content scriptはDOMを読み取り・変更できる。[S05] |
| 区別が必要 | Conversations APIはResponses API向け会話状態管理。ChatGPTの既存履歴操作へ接続できるとは扱わない。[S04] |
| 未確認 | 一般ユーザーの両Web履歴を列挙・削除する公開APIの適用方法。本資料はAPIが絶対に存在しないという断定ではない。 |
| 未確認 | 実際の画面での網羅的列挙、正確な対象照合、自動削除、削除成功検証。 |

### 規約・公開可否の判定

技術的に動くこと、サービスの許可範囲、Chrome Web Storeの審査適合は別の判定とする。OpenAIの自動抽出条項と、Anthropicの自動アクセス等の条項を操作別に確認する。[S11][S12]

規約は居住地・アカウントの契約区分で適用版が異なり得る。取得したAnthropic Consumer Termsには地域限定の記述があるため、それだけを日本の全利用者へ一律適用しない。[S12][S13]

不明点は未解決として記録し、必要な許可や専門的な確認を得る。チェックボックスへの同意やOSS公開だけで利用条件の問題が解消したとは扱わない。

必須：FR01〜07、FR10〜12。FR08は削除補助として分離。FR09は企画上の主要要件だが、技術・許可範囲・安全条件を満たすまで出荷を停止する。タグ、保存検索、名称変更はMVP後の候補。

### 作らない機能

外部AI分類、広告、利用統計、クラウド同期、常時巡回、スケジュール削除、アカウント認証の代行、非公開APIに依存した取得、認証情報の抽出は初期版に含めない。

## 04 / 画面と利用フロー

### 管理画面

拡張専用タブに配置する。左にサービスと検索、中央に履歴一覧、右にプレビュー、下部に選択件数と操作。別サービスの会話本文をChatGPT/Claudeのページ内へ渡さない。

```text
接続/取り込み → 取得範囲を確認 → 検索・KEEP
→ 対象選択 → 削除予定 → 最終確認 → 実行 → 結果照合
```

### 一覧に必須の表示

サービス、タイトル、日時（取得できた場合）、KEEP、取得元、本文取得の有無。ヘッダーには「取得済み128件 / 全件数不明」のように、未知の総数を正直に示す。「全部選択」は「取得済み128件を選択」と表示する。

### 削除予定画面

対象のアカウント/ワークスペース、件数、KEEP除外件数、未確認の対象、取得時刻、更新検知の限界、取り消し不可を表示する。主体が未検証の対象と、更新状態を安全に確認できない対象は、自動削除の承認対象に入れない。

### 処理中と停止

処理中の1件、残件数、成功/未確認/失敗を表示する。停止は以降の操作を止めるもので、すでにサービスへ送られた削除を取り消すものではない。タブ閉鎖や権限失効は停止として扱う。

### 結果画面

「UI上で削除を確認」「結果未確認」「KEEPのため除外」「状態変更のため保留」等を区別する。バックエンドでの完全消去まで保証しない。自動再試行は行わず、不明な対象は利用者に手動確認を案内する。

### アクセシビリティ

キーボード操作、フォーカス復帰、スクリーンリーダー用ラベル、色以外の状態表現、長いタイトルの読み取りに対応する。Enterの連打で削除承認と実行を連鎖させない。

## 05 / 構成と権限

### 提案する構成

```text
Extension UI (TypeScript / React候補)
  ├─ Domain: 検索・KEEP・削除計画・安全判定
  ├─ Import Worker: 公式エクスポート解析
  └─ Controller: 承認・逐次処理・停止
       ├─ ChatGPT Adapter / Content Script
       └─ Claude Code Web Adapter / Content Script
```

Manifest V3を前提とする。TypeScript/React/ビルドツールの採用とバージョンは開発時に固定する。本資料には実装済み拡張や実サービス用セレクターは含まれない。

| 権限/機能 | 方針 |
| --- | --- |
| activeTab / scripting | 利用者が対象タブで開始したときの一時アクセスを第一候補にする。[S06] |
| storage | 設定と同意済みの管理状態だけ。content scriptからの直接読み取りを制限。[S08] |
| host permissions | 必要性を実証した場合のみ対象オリジンに限定して任意追加。 |
| 不採用 | <all_urls>、cookies、history、webRequest、debugger、nativeMessagingを初期要件にしない。 |

### コンテキスト分離

主体の照合、計画、承認は拡張側で扱う。content scriptには、対象サービスの現在処理する1件に必要な最小情報だけ渡す。通信の送信元、タブ、フレーム、URL、実行トークンを検証する。ページのpostMessageで削除を開始させない。

### ライフサイクル

Service Workerは終了し得る。[S07] 連続処理は終了・再起動で必ず停止扱いにする。ブラウザーや拡張の再起動後は承認を無効にし、再照合・再承認なしで続きを実行しない。

## 06 / データモデルと保存

| 情報 | 保存方針 |
| --- | --- |
| 会話本文・タイトル | 標準は作業中のメモリのみ。ログと永続検索索引へ残さない。 |
| KEEP・タグ・識別情報 | 明示同意した場合のみ端末内保存。暗号化と鍵管理を別途設計。 |
| 認証情報 | Cookie、セッショントークン、APIキーを取得・保管・中継しない。 |
| 削除計画と承認 | 標準はメモリ。永続化する場合も承認は復元せず、再確認を必須にする。 |
| 診断情報 | エラーコードや版だけ。本文・URL・IDは通常ログに出さない。 |
| 同期と外部送信 | storage.sync、外部解析、エラーテレメトリ、外部AIを使わない。 |

### 識別キー

provider + accountScope + workspaceScope + conversationIdを複合キーとする。タイトルや一覧の順番は主キーにしない。アカウント表示名だけで主体を確認したことにしない。元データから安定識別できなければ、自動削除は不可。

### KEEPの安全性

KEEPストアに版番号を持ち、削除確定直前に読み直す。復号失敗、破損、読み取り失敗、競合は「KEEPなし」ではなく停止。初回の明示的な空ストア作成と、既存状態の消失を区別する。

### 暗号化の限界

暗号鍵を暗号文と同じ場所へ平文保存しない。ユーザーによるロック解除、KDF、AEAD、鍵消去、移行と破損復旧を脅威モデルに基づいて選定する。安全な鍵管理を実装できない段階では永続保存機能を出荷しない。

ローカル保存や識別子のハッシュ化は匿名化の保証ではない。ツールが本文を保存しなくても、元エクスポート・サービス側データ・OSのバックアップまで消えるわけではない。保存APIの挙動は[S08]を参照。

## 07 / 削除プロトコル

### 安全条件

利用者の明示承認、対象IDの固定、主体一致、KEEPの再確認、未変更状態、対応済み画面、対象1件の一致、必要権限、実行中でないことをすべて満たす。1つでも不明なら停止する。

```text
draft → ready → approved → running → completed
                         ├→ paused
                         ├→ failed
                         └→ uncertain
paused / uncertain → 再照合・新しい承認 → running
```

### 計画の固定

選別時点の対象集合を不変のスナップショットにする。実行時に検索条件を再評価して対象を追加しない。計画には主体、サービス、対象ID、状態証拠、KEEP版、Adapter版、期限を含める。変更したら承認を破棄する。

### 1件ずつの実行

最新状態を照合し、削除導線を開き、確認画面の対象をもう一度照合してから確定する。任意の「Delete」文字列や座標のクリック、タイトルだけの照合は禁止。並列削除はしない。

### 競合と不確実性

同じ主体を扱う削除ワーカーは1つにする。KEEP更新と確定指示を同一の制御経路で順序付ける。ただしサーバー側で進行中の削除を後からKEEPで取り消せないことは表示する。

画面操作では、照合から削除までの間に外部更新が入る競合を原子的に防げない可能性がある。上流の条件付き操作がない限り、完全な競合防止を保証しない。十分な更新・稼働状態を検出できないAdapterは手動補助までに制限する。

### 結果検証

成功通知と再読み込み後の状態等、Adapterで定義した複数の証拠を評価する。一覧から消えただけ、ページが404になっただけ、タイムアウトしただけでは成功としない。不明な破壊的操作の自動再試行は禁止。

## 08 / サービス別の実現性検証

### ChatGPT

公式エクスポートの解析から開始できる。[S03] ZIP内形式、分割JSON、分岐会話、添付物、アーカイブ、プロジェクト等は実データで確認し、形式を固定事実として扱わない。本文の分岐を勝手に連結しない。

Web画面について、安定した会話ID、主体情報、更新状態、削除確認の対象情報、再読み込み後の結果を取得できるか検証する。エクスポートと現在のアカウントを結び付けられない場合は、自動削除に使用しない。

### Claude Code on the web

対象はクラウドセッション一覧と個別セッション画面。[S02] 通常ClaudeチャットのDOMやローカルJSONLは代替しない。アーカイブ、古い履歴、組織切替、進行中セッションの扱いを確認する。

ローカルAgent SDKを使えることをWeb削除の根拠にしない。公式エクスポートにクラウドセッションが含まれるか、取得形式は何かも未確認として扱う。必要情報を安全に取れなければ、自動削除を無効化する。

## 09 / セキュリティと入力処理

### 信頼境界

Webページ、会話本文、取り込みファイル、外部リンク、content scriptのメッセージを未信頼入力として扱う。会話に含まれる命令はツールの命令ではない。ページ由来の値だけで削除許可を生成しない。

| 脅威 | 要求する防御 |
| --- | --- |
| HTML/スクリプト混入 | 文字列として描画。必要なMarkdownは限定的にサニタイズ。 |
| 外部通信/追跡 | 外部画像・フォント・iframe・解析SDKを自動読み込みしない。 |
| ZIP爆弾/過大入力 | 圧縮前後サイズ、件数、階層深さ、処理時間の上限。中止可能。 |
| 不正パス/URL | ファイル名をパスへ直接使わない。URLは許可したオリジンと形式のみ。 |
| メッセージ偽装 | sender、tabId、frameId、document/route、スキーマ、期限を検証。 |
| クロスサービス漏えい | 別Adapterへ本文や他サービスの一覧を送らない。 |
| 依存物/更新の改ざん | 依存固定、レビュー、ビルド追跡、公開権限と秘密情報の保護。 |

### コードの配布

実行コードは拡張へ同梱し、リモートJS/WASMや外部設定による削除ロジックの差し替えを行わない。[S10] DOM変更時は、安全停止と新リリースで対応する。

### 不具合報告

架空データと再現手順を標準にする。実会話・エクスポート全体・認証情報をIssueへ貼るよう求めない。診断ファイルの出力は利用者が内容を確認してから明示的に行う。

### 限界

悪意ある同一端末の別ソフトや侵害されたサービスページまで完全に防げるとは説明しない。権限分離と停止条件はリスクを減らす設計であり、絶対安全の保証ではない。

### 試験層

Domain単体試験、合成DOMでのAdapter試験、Chrome拡張の統合試験、許可済みテスト会話での実サービス試験を分ける。実画面試験を、モック試験で代替したと報告しない。

### 性能試験の提案

架空の1,000件/10,000件で検索、ページング、プレビュー、中止、メモリ使用量を測る。初回PoCで端末条件と計測指標を決め、基準値は実測後に合意する。巨大履歴も無制限に対応すると宣伝しない。

### 出荷停止条件

誤削除、KEEP無視、主体の誤照合、認証情報の取得、未承認通信、成功の誤判定が1件でも再現すれば削除機能を出荷しない。未解決のテストを合格扱いにせず、対象機能を未対応と明示する。

## 12 / OSS公開と制約

### 公開前の必須資料

README、LICENSE、PRIVACY、SECURITY、権限説明、対応表、既知の制約、テスト手順、依存ライセンス一覧、ビルド手順、リリースノートを揃える。ローカルだけの処理でもデータ開示とプライバシーポリシーが必要。[S09]

### ライセンスとブランド

自作部分のライセンスはMITを候補とし、権利者と公開責任者の承認で確定する。依存物・素材・商標は別途確認。LizyChatTidyの商標、既存ソフト、ストア名、ドメインの衝突は本資料では調査していない。

OpenAI/Anthropicの公式製品・公認製品のように表示しない。対応サービス名は説明目的で扱い、ロゴ利用は独立して確認する。[S13]

### ビルドと配布

依存物とツールチェーンを固定し、クリーン環境からストア提出ZIPを生成する。ソースのタグ、コミット、ビルド条件、SHA-256を紐付ける。ストア署名を含む配布物の完全一致は未検証のまま約束しない。

### 公開機能の区分

整理機能と自動削除は独立して有効化する。許可範囲・技術・安全性が未確認の自動操作は配布版に入れない。レビュー不足を「実験版」の注意書きだけで代替しない。

### この資料で未実施のこと

実装、ログイン済み実画面の確認、実会話の削除、35件の受け入れ試験、ストア申請、第三者監査、商標調査は未実施。型定義の構文/型検査や文書整形の確認と、製品の動作検証を混同しない。
